# Découverte M2 : cache local et ARP explicite

Par défaut, `nettracker scan-once --config config.toml` lit une fois la table de voisins du système et enregistre uniquement les adresses IPv4 privées présentes dans `allowed_subnets`. Il ne lance aucun balayage ARP. Un cache vide ne signifie pas qu'aucun appareil n'est connecté. Sous Linux, la lecture utilise `ip -4 neigh show` (`ip` est requis) ; sous Windows, `arp -a`.

Pour activer un seul passage ARP, il faut réunir trois conditions : `scan.mode = "active"` dans la configuration, `--enable-active` sur la ligne de commande, et `--target` avec une adresse IPv4 ou un CIDR privé explicitement autorisé. Exemple à adapter exclusivement à son propre réseau : `nettracker scan-once --config config.toml --enable-active --target 192.168.1.0/24`. La cible doit être contenue dans `allowed_subnets` ; les CIDR de plus de 256 adresses sont refusés. Ne lancez pas cet exemple sur un réseau qui ne vous appartient pas ou que vous n'êtes pas autorisé à analyser.

Si l'ARP brut n'est pas disponible, notamment sans Npcap sous Windows ou sans droits de paquets bruts sous Linux, la commande bascule sur la table de voisins locale et affiche `Degraded mode: system neighbor cache only`. Les observations sont alors enregistrées en mode passif ; un échec de lecture du cache reste une erreur. Scapy et les droits réseau nécessaires au mode actif doivent être présents sur la machine cible ; ils ne sont pas requis pour le mode passif. Aucun test n'a encore validé le comportement sur le matériel ou le réseau du propriétaire.

Un CSV IEEE MA-L local peut être fourni avec `--oui-file CHEMIN` dans les deux modes. Aucun téléchargement n'est automatique ; un fichier absent ou mal formé est refusé. Une MAC localement administrée ne reçoit pas de fabricant déduit. La source officielle et les réserves d'interprétation figurent dans `data/oui/README.md`.

Les tests utilisent des lecteurs simulés, des adresses inventées et SQLite temporaire : ils n'émettent aucun paquet et ne vérifient pas Npcap ni les droits Linux réels. Le repli est visible dans la sortie console et les logs, pas encore dans un dashboard. Les suggestions de fusion de MAC aléatoires, les noms réseau, les autres sources de découverte et la vérification sur machines cibles restent à faire avant de déclarer M2 complet.
