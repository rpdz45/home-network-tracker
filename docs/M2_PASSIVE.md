# Découverte M2 : cache, ARP et nmap

Par défaut, `nettracker scan-once --config config.toml` lit une fois la table de voisins du système et enregistre uniquement les adresses IPv4 privées présentes dans `allowed_subnets`. Il ne lance aucun balayage ARP. Un cache vide ne signifie pas qu'aucun appareil n'est connecté. Sous Linux, la lecture utilise `ip -4 neigh show` (`ip` est requis) ; sous Windows, `arp -a`.

Pour activer un seul passage ARP, il faut réunir trois conditions : `scan.mode = "active"` dans la configuration, `--enable-active` sur la ligne de commande, et `--target` avec une adresse IPv4 ou un CIDR privé explicitement autorisé. Exemple à adapter exclusivement à son propre réseau : `nettracker scan-once --config config.toml --enable-active --target 192.168.1.0/24`. La cible doit être contenue dans `allowed_subnets` ; les CIDR de plus de 256 adresses sont refusés. Ne lancez pas cet exemple sur un réseau qui ne vous appartient pas ou que vous n'êtes pas autorisé à analyser.

Si l'ARP brut n'est pas disponible, notamment sans Npcap sous Windows ou sans droits de paquets bruts sous Linux, la commande bascule par défaut sur la table de voisins locale et affiche `Degraded mode: system neighbor cache only`. Les observations sont alors enregistrées en mode passif ; un échec de lecture du cache reste une erreur. Scapy et les droits réseau nécessaires au mode actif doivent être présents sur la machine cible ; ils ne sont pas requis pour le mode passif. Aucun test n'a encore validé le comportement sur le matériel ou le réseau du propriétaire.

Un CSV IEEE MA-L local peut être fourni avec `--oui-file CHEMIN` dans les deux modes. Aucun téléchargement n'est automatique ; un fichier absent ou mal formé est refusé. Une MAC localement administrée ne reçoit pas de fabricant déduit. La source officielle et les réserves d'interprétation figurent dans `data/oui/README.md`.

La résolution DNS inverse est désactivée par défaut. `--resolve-names` l'active uniquement après validation de l'adresse dans `allowed_subnets` ; le résolveur système peut néanmoins émettre des requêtes DNS hors du LAN. Lorsqu'une MAC aléatoire au statut `to_confirm` partage un nom avec un appareil connu plus ancien et que leurs périodes observées ne se chevauchent pas, un événement `merge_suggested` est créé une seule fois par paire. Le mécanisme fonctionne aussi si le nom n'est obtenu qu'à un passage ultérieur. Il ne fusionne jamais automatiquement les appareils et n'envoie aucune notification.

Les tests utilisent des lecteurs simulés, des adresses inventées et SQLite temporaire : ils n'émettent aucun paquet et ne vérifient pas Npcap ni les droits Linux réels. Le repli est visible dans la sortie console et les logs, pas encore dans un dashboard. mDNS, la liste blanche `known_devices`, la validation sur Windows/Linux/Raspberry Pi et la vérification sur le réseau autorisé du propriétaire restent à faire avant de déclarer M2 complet.


## Repli nmap optionnel

Dans `[scan]`, `nmap_fallback = true` autorise un repli supplémentaire après une erreur ARP. Ce réglage ne suffit pas seul : le mode actif, `--enable-active` et `--target` restent obligatoires. Un succès ARP, même vide, ne déclenche pas nmap. `nmap_timeout_seconds` vaut 30 par défaut, accepte 1 à 120 secondes et borne la durée du sous-processus. Le binaire `nmap` doit être installé séparément et disponible dans le `PATH`.

La commande utilise uniquement les options fixes `-sn -n --max-rate 10 --max-retries 1 --host-timeout 5s -oX -` et la cible privée validée (256 adresses au maximum). Aucun shell, scan de ports, script NSE ou service n’est demandé. `-sn` reste actif : selon la plateforme et les droits, nmap utilise des sondes ARP ou ICMP/TCP de découverte. `-n` interdit la résolution DNS par nmap. Le débit demandé à nmap n’est pas une garantie sur toutes les trames ARP du système.

Une réussite affiche `Degraded mode: nmap host discovery fallback (active)` et la source `active_nmap` ; SQLite enregistre alors le scan en mode actif. Si nmap est absent, refuse les droits, dépasse le délai ou produit un XML inexploitable, le cache système reste le dernier repli visible. Une erreur de périmètre se propage sans autre tentative.

Le XML doit annoncer une fin réussie. Les entités XML et références externes sont interdites ; au-delà de 1 Mio de caractères la sortie est refusée. Cette limite est vérifiée après capture et ne borne donc pas la mémoire du sous-processus ni sa sortie pendant l’exécution. Les adresses IPv4 retournées doivent appartenir à la cible exacte ; seules les MAC unicast valides sont retenues. Les hôtes sans MAC exploitable sont signalés et, si aucun hôte en ligne n’a de MAC utilisable, le cache est tenté. Les hôtes IPv6 seuls ne sont pas pris en charge. Aucun appel nmap réel, ni validation Npcap ou privilèges sur matériel, n’a été réalisé.
